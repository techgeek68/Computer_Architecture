**Theory**


**Pipelining**

To enhance CPU performance, we have two primary options:
  * Enhance hardware by introducing faster circuits.
  * Organize the hardware to enable the concurrent execution of multiple operations.

Given the limitations on hardware speed and the high cost associated with faster circuits, the latter option becomes more favorable.

Pipelining is a technique for configuring CPU hardware elements to boost overall performance. In a pipelined processor, multiple instructions can be executed simultaneously by overlapping their stages of execution.

**Real World Analogy: Water Bottle Packaging Plant**

Consider a water bottle packaging plant with three stages:
  - **Stage 1 (I):** Insert the bottle
  - **Stage 2 (F):** Fill water in the bottle
  - **Stage 3 (S):** Seal the bottle

Each stage takes 1 minute to complete.

**Without Pipelining (3 bottles):**
```
Bottle 1:  I    F    S    ·    ·    ·    ·    ·    ·
Bottle 2:  ·    ·    ·    I    F    S    ·    ·    ·
Bottle 3:  ·    ·    ·    ·    ·    ·    I    F    S
           ─────────────────────────────────────────
           1    2    3    4    5    6    7    8    9   (minutes)

Total Time = 9 minutes
Average time per bottle = 9 / 3 = 3 minutes
```

**With Pipelining (3 bottles):**
```
Bottle 1:  I    F    S    ·    ·
Bottle 2:  ·    I    F    S    ·
Bottle 3:  ·    ·    I    F    S
           ─────────────────────
           1    2    3    4    5   (minutes)

Total Time = 5 minutes
Average time per bottle = 5 / 3 ≈ 1.67 minutes
```

Thus, pipelined operation increases the efficiency of the system by keeping all stages active simultaneously.

**Design of a Basic Pipeline**

In a pipelined processor:

 - A pipeline has two ends: the **input end** and the **output end**.
 - Between these ends, there are multiple **stages/segments** such that the output of one stage is connected to the input of the next stage.
 - Each stage performs a specific operation.
 - **Interface registers** (also called latches or buffers) are used to hold the intermediate output between two stages.
 - All stages in the pipeline, along with the interface registers, are controlled by a **common clock**.

```
┌─────────┐    ┌─────────┐    ┌─────────┐    ┌─────────┐    ┌─────────┐
│ Stage 1 │───►│ Stage 2 │───►│ Stage 3 │───►│ Stage 4 │───►│ Stage 5 │
│  (IF)   │ R1 │  (ID)   │ R2 │  (EX)   │ R3 │  (MEM)  │ R4 │  (WB)   │
└─────────┘    └─────────┘    └─────────┘    └─────────┘    └─────────┘
     ▲              ▲              ▲              ▲              ▲
     └──────────────┴──────────────┴──────────────┴──────────────┘
                              Common Clock
```

**Execution in a Pipelined Processor**

The execution sequence of instructions in a pipelined processor can be visualized using a space time diagram. For a processor with 4 stages executing 2 instructions:

- Non overlapped execution:
  - Total time = 4 + 4 = 8 cycles

- Overlapped (pipelined) execution:
  - Total time = 4 + (2 − 1) = 5 cycles

**RISC 5 Stage Instruction Pipeline**

A RISC processor has a 5 stage instruction pipeline:

| Stage | Name | Description |
|-------|------|-------------|
| **IF** | Instruction Fetch | The CPU reads the instruction from memory at the address in the program counter. |
| **ID** | Instruction Decode | The instruction is decoded, and operands are read from the register file. |
| **EX** | Execute | ALU operations are performed. |
| **MEM** | Memory Access | Memory operands are read from or written to memory. |
| **WB** | Write Back | The computed or fetched value is written back to the destination register. |


**Speedup Equation**

The speedup of a pipelined processor over a non pipelined processor is given by:

$$S = \frac{k \times n}{k + n - 1}$$

Where:
- **k** = number of pipeline stages
- **n** = number of instructions

**Derivation:**

| Execution Type | Time Calculation | Explanation |
|----------------|------------------|-------------|
| Without Pipelining | T₁ = k × n cycles | Each instruction takes k cycles sequentially |
| With Pipelining | Tₖ = k + (n − 1) cycles | First instruction takes k cycles; each subsequent instruction completes in 1 additional cycle |

Therefore:

$$Speedup = \frac{T_1}{T_k} = \frac{k \times n}{k + n - 1}$$

**Properties:**

1. As n → ∞, the speedup approaches k (the theoretical maximum).
2. The speedup is always less than or equal to k.
3. Pipeline efficiency: η = S/k × 100%

**Pipeline Hazards**

In real processors, three types of hazards can disrupt ideal pipeline performance:

| Hazard Type | Cause | Solution |
|-------------|-------|----------|
| **Data Hazard** | Instruction depends on the result of a previous instruction not yet completed | Data forwarding, pipeline stalls (bubbles), NOP insertion |
| **Control Hazard** | Branch instruction causes uncertainty about next instruction | Branch prediction, delayed branching, speculative execution |
| **Structural Hazard** | Two instructions need the same hardware resource simultaneously | Resource duplication (e.g., separate instruction and data caches) |

**Discussion and Conclusions**

This laboratory experiment successfully demonstrated the fundamental concepts of pipelining and its impact on processor performance. The speedup equation S = (k × n) / (k + n − 1) was verified experimentally, showing that with k=5 stages and n=20 instructions, a speedup approaching the theoretical maximum was achieved. 

The floating point pipeline demonstration illustrated how complex operations are decomposed into stages (Fetch -> Normalize -> Execute -> Round) for efficient execution. The space time diagram visualization confirmed that pipelined execution reduces total time from k × n cycles to k + n − 1 cycles, achieving significant performance improvement. 

The experiment also highlighted that pipeline stalls reduce effective throughput, emphasizing the importance of hazard mitigation in real processors. Overall, pipelining remains a fundamental technique for enhancing CPU performance by enabling concurrent instruction execution through temporal parallelism.
