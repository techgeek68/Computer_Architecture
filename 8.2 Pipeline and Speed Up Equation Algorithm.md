# Algorithm: Pipelined Floating Point Arithmetic & Speedup Analysis

The code demonstrates IEEE 754 floating point internals and CPU pipeline performance metrics.

**1. Data Structures & Type Definitions**

```
1.1. FPU (Floating Point Union):
     - Allows viewing the same 32 bits as float OR uint32_t
     - Enables bit manipulation of IEEE 754 representation

1.2. FPC (Floating Point Components):
     - sign: 1 bit (0=positive, 1=negative)
     - exp: 8 bits (biased exponent, bias=127)
     - mant: 23 bits (mantissa/fraction without implicit 1)
```

**2. IEEE 754 Decomposition Functions**

**2.1 fp_split() - Extract Components**
```
INPUT: float v
PROCESS:
  2.1.1. Reinterpret float bits as uint32_t via union
  2.1.2. Extract sign:     bits[31]      → (u >> 31)
  2.1.3. Extract exponent: bits[30:23]   → (u >> 23) & 0xFF
  2.1.4. Extract mantissa: bits[22:0]    → u & 0x7FFFFF
OUTPUT: FPC structure {sign, exp, mant}

IEEE 754 Single Precision Layout:
┌────┬──────────┬───────────────────────┐
│ S  │ Exponent │      Mantissa         │
│ 1b │   8 bits │       23 bits         │
└────┴──────────┴───────────────────────┘
 31   30      23 22                     0
```

**2.2 fp_join() - Reconstruct Float**
```
INPUT: FPC structure {sign, exp, mant}
PROCESS:
  2.2.1. Combine: (sign << 31) | (exp << 23) | (mant & 0x7FFFFF)
  2.2.2. Reinterpret uint32_t bits as float via union
OUTPUT: Reconstructed float value
```

**3. Floating-Point Pipeline Simulation (fp_pipeline)**

```
INPUT: float a, float b, char op ('+' or '-')
```

**Stage 1: Decode Operands**
```
3.1.1. Split both operands into components:
         ca = fp_split(a) → {sign_a, exp_a, mant_a}
         cb = fp_split(b) → {sign_b, exp_b, mant_b}
3.1.2. Convert biased exponents to actual:
         ea = exp_a - 127
         eb = exp_b - 127
```

**Stage 2: Exponent Alignment**
```
3.2.1. Calculate exponent difference: diff = |ea - eb|
3.2.2. IF ea < eb:
         Swap operands (larger exponent = reference)
3.2.3. Set result exponent: rexp = max(ea, eb)
```

**Stage 3: Mantissa Preparation**
```
3.3.1. Restore implicit leading 1:
         ma = (1 << 23) | ca.mant  → 24-bit value: 1.xxxxxxx
         mb = (1 << 23) | cb.mant
3.3.2. Align smaller mantissa by right-shifting:
         mb = mb >> diff  (loses precision for large diff)

Example: 8.5 + 0.25
  8.5  = 1.0001 × 2³   → ma = 1.0001, exp=3
  0.25 = 1.0000 × 2⁻²  → mb = 1.0000, exp=-2
  diff = 5, align: mb >>= 5 → 0.00001
```

**Stage 4: Mantissa Operation**
```
3.4.1. Determine effective operation:
         - Addition (+): effective_sub = (signs differ)
         - Subtraction (-): effective_sub = (signs same)

3.4.2. IF effective subtraction:
         mr = |ma - mb|
         sr = sign of larger magnitude
       ELSE (effective addition):
         mr = ma + mb
         sr = common sign
```

**Stage 5: Normalization**
```
3.5.1. IF mr == 0:
         Result is zero, set exponent to minimum (-127)

3.5.2. ELSE IF overflow (bit 24 set, mr >> 24):
         Right shift mantissa: mr >>= 1
         Increment exponent: rexp++

3.5.3. ELSE IF underflow (bit 23 not set):
         WHILE leading 1 not in position 23:
           Left shift mantissa: mr <<= 1
           Decrement exponent: rexp--

3.5.4. Mask to 23 bits: mr &= 0x7FFFFF
```

**Stage 6: Result Assembly**
```
3.6.1. Reconstruct float: result = fp_join({sr, rexp+127, mr})
3.6.2. Compare with hardware result: expected = a ± b
3.6.3. Calculate error: |result - expected|
OUTPUT: Pipelined result, expected value, error magnitude
```

**4. Pipeline Speedup Analysis**

**4.1 speedup_analysis() - Performance Metrics**
```
INPUT: k (stages), n (operations), stalls (pipeline hazards)

FORMULAS:
  4.1.1. Sequential time:   T_seq  = k × n
         (Each operation takes k cycles, done serially)

  4.1.2. Pipelined time:    T_pipe = k + (n-1) + stalls
         (k cycles to fill pipe, then 1 op/cycle, plus hazard stalls)

  4.1.3. Speedup:           S = T_seq / T_pipe

  4.1.4. Efficiency:        E = S / k × 100%
         (How close to the theoretical max speedup of k)

  4.1.5. Throughput:        Th = n / T_pipe ops/cycle

  4.1.6. CPI:               Cycles Per Instruction = T_pipe / n

  4.1.7. Cycles Saved:      T_seq - T_pipe

OUTPUT: All computed metrics
```

**4.2 speedup_table() - Varying Operation Count**
```
INPUT: k (number of pipeline stages)
PROCESS:
  FOR n IN {1, 2, 5, 10, 20, 50, 100, 200, 500, 1000}:
    Calculate T_seq, T_pipe, Speedup, Efficiency, Savings%
    Print row

KEY INSIGHT: As n → ∞, Speedup → k (theoretical maximum)
```

**5. Pipeline Execution Diagram (pipeline_diagram)**

```
INPUT: k (stages, max 8), n (operations, max 10)
PROCESS:
  5.1. Define stage names: IF, ID, EX, MM, WB, S6, S7, S8
  5.2. Total cycles needed: cycles = k + n - 1
  5.3. FOR each instruction i (0 to n-1):
         FOR each cycle c (0 to cycles-1):
           stage_index = c - i
           IF 0 ≤ stage_index < k:
             Print stage name
           ELSE:
             Print "." (idle)
OUTPUT: Visual pipeline diagram

Example (k=5, n=4):
     Cycle: 1   2   3   4   5   6   7   8
     I1:    IF  ID  EX  MM  WB  .   .   .
     I2:    .   IF  ID  EX  MM  WB  .   .
     I3:    .   .   IF  ID  EX  MM  WB  .
     I4:    .   .   .   IF  ID  EX  MM  WB
            ←─── k cycles to fill ───→
            Total = k + n - 1 = 5 + 4 - 1 = 8 cycles
```
