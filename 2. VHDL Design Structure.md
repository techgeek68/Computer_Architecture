# VHDL Design Structure: Entities, Architectures, and Modeling Styles

---

**VHDL structure**

VHDL (VHSIC Hardware Description Language) is an IEEE standardized language for describing digital circuits. Its structure has three main parts:

| Section | Purpose |
|---|---|
| **Library** | Imports standard packages (e.g., `IEEE.STD_LOGIC_1164`) |
| **Entity** | Defines the interface; inputs & outputs (the "what") |
| **Architecture** | Defines the internal logic (the "how") |

Architecture can be written in three styles: Behavioral, Structural, or Dataflow.

---

**Libraries**

A VHDL library is a collection of precompiled packages containing types, functions, and components that can be reused across designs.

| Library | Package | Purpose |
|---|---|---|
| `IEEE` | `STD_LOGIC_1164` | Defines `std_logic` and `std_logic_vector` types |
| `IEEE` | `NUMERIC_STD` | Arithmetic on `signed`/`unsigned` types |
| `IEEE` | `MATH_REAL` | Real number math functions |
| `STD` | `TEXTIO` | File I/O for simulation |
| `WORK` | *(user defined)* | Default library for your own designs |

- Syntax:
```vhdl
library IEEE;
use IEEE.STD_LOGIC_1164.ALL;        -- all items from package
use IEEE.NUMERIC_STD.ALL;

library WORK;
use WORK.my_package.my_function;    -- specific item
```

- Custom Library Example
```vhdl
package my_package is
    constant WIDTH : integer := 8;
    function add(a, b : integer) return integer;
end my_package;

package body my_package is
    function add(a, b : integer) return integer is
    begin
        return a + b;
    end add;
end my_package;
```

> Note: The packages `std_logic_arith`, `std_logic_signed`, and `std_logic_unsigned` are Synopsys proprietary packages, not official IEEE standard packages. The IEEE standard replacement is `ieee.numeric_std`, which should be preferred.

---

**Basic Elements of VHDL:**

There are the following three basic elements of VHDL:

**1. Entity**

The Entity is used to specify the input and output ports of the circuit. An Entity usually has one or more ports that can be inputs (`in`), outputs (`out`), input-outputs (`inout`), or `buffer`.

An Entity may also include a set of generic values that are used to declare properties of the circuit.

**Rules for writing Port name:**

- Port name consists of letters, digits, and underscores.
- It always begins with a letter.
- Port name is case insensitive.

**Modes of Port:**

| Mode | Description |
|---|---|
| `in` | Input port. Port can be read. |
| `out` | Output port. Port can be written (readable in VHDL 2008). |
| `inout` | Bidirectional port. Port can be read and written. |
| `buffer` | Buffered output port. Port can be read and written. It can have only one source (relaxed in VHDL-2008). |

**Simplified syntax:**

```vhdl name=entity_syntax.vhd
entity NAME_OF_ENTITY is
    port (
        signal_names : mode type;
        signal_names : mode type;
        signal_names : mode type
    );
end NAME_OF_ENTITY;
```

**Example:**

```vhdl name=orgate_entity.vhd
entity orgate is
    port (
        a : in  std_logic;
        b : in  std_logic;
        c : out std_logic
    );
end orgate;
```

**Using Generic:**

If an entity is generic, then it must be declared before the ports. Generic does not have a mode, so it can only pass information into the entity.

**Syntax:**

```vhdl name=generic_syntax.vhd
entity entity_name is
    generic (
        generic_1_name : data_type;
        generic_2_name : data_type;
        generic_n_name : data_type
    );
    port (
        port_1_name : mode data_type;
        port_2_name : mode data_type;
        port_n_name : mode data_type
    );
end entity_name;
```

**Example:**

```vhdl name=logic_gates_entity.vhd
entity Logic_Gates is
    generic (
        Delay : time := 10 ns
    );
    port (
        Input1 : in  std_logic;
        Input2 : in  std_logic;
        Output : out std_logic
    );
end Logic_Gates;
```


**2. Architecture**

The architecture body specifies how the circuit operates and how it is implemented. An entity or circuit can be specified in behavioral, structural (interconnected components), or a combination of the above.

**Syntax:**

```vhdl name=architecture_syntax.vhd
architecture architecture_name of NAME_OF_ENTITY is
    -- Declarations
    -- component declarations
    -- signal declarations
    -- constant declarations
    -- function declarations
    -- procedure declarations
    -- type declarations
begin
    -- Statements
end architecture_name;
```

**Example:**

```vhdl name=andgate_architecture.vhd
architecture synthesis of andgate is
begin
    c <= a AND b;
end synthesis;
```


**3. Configuration**

A configuration defines how the design hierarchy is linked together. It is also used to associate an architecture with an entity.

**Syntax:**

```vhdl name=configuration_syntax.vhd
configuration configuration_name of entity_name is
    for architecture_name
        for instance_label : component_name
            use entity library_name.entity_name(architecture_name);
        end for;
        -- additional configuration declarations
    end for;
end configuration configuration_name;
```

**Example:**

```vhdl name=demo_config.vhd
configuration demo_config of even_detector_testbench is
    for tb_archi
        for uut : even_detector
            use entity work.even_detector(sop_archi);
        end for;
    end for;
end demo_config;
```

**Levels of representation and abstraction**

A digital system can be represented at different levels of abstraction. This keeps the description and design of complex systems manageable.


**Data Flow Modeling**

In this modeling style, the flow of data through the entity is expressed using concurrent (parallel) signals. The concurrent statements in VHDL are `WHEN` and `GENERATE`.

Besides them, assignments using only operators (`AND`, `NOT`, `+`, `*`, `sll`, etc.) can also be used to construct code.

In concurrent code, the following can be used:

- Operators
  - The `WHEN` statement (`WHEN/ELSE` or `WITH/SELECT/WHEN`)
  - The `GENERATE` statement
  - The `BLOCK` statement (rarely used in practice)


**Behavioral Modeling**

In this modeling style, the behavior of an entity as a set of statements is executed sequentially in the specified order. Only statements placed inside a `PROCESS`, `FUNCTION`, or `PROCEDURE` are sequential.

`PROCESSES`, `FUNCTIONS`, and `PROCEDURES` are the only sections of code that are executed sequentially. However, as a whole, any of these blocks is still concurrent with any other statements placed outside it.

One important aspect of behavioral code is that it is not limited to sequential logic. Indeed, with it, we can build sequential circuits as well as combinational circuits.

The behavioral statements are `IF`, `WAIT`, `CASE`, and `LOOP`.

`VARIABLES` are restricted to sequential code only (inside `PROCESS`, `FUNCTION`, or `PROCEDURE`). A regular `VARIABLE` is local in scope, so its value cannot be passed out directly. However, `SHARED VARIABLES` (VHDL-1993+) can have a broader scope, though their use is discouraged due to potential race conditions. In VHDL-2000 and later, shared variables must be of a protected type.


**Structural Modeling**

In this modeling, an entity is described as a set of interconnected components. A component instantiation statement is a concurrent statement. Therefore, the order of these statements is not important.

The structural style of modeling describes only an interconnection of components (viewed as black boxes), without implying any behavior of the components themselves or of the entity that they collectively represent.

In structural modeling, the architectural body is composed of two parts:

  - Declarative part (before the keyword `begin`)
  - Statement part (after the keyword `begin`)
