**Theory**

**Pipelining**

To enhance CPU performance, we have two primary options:
  * Enhance hardware by introducing faster circuits.
  * Organize the hardware to enable the concurrent execution of multiple operations.

Given the limitations on hardware speed and the high cost associated with faster circuits, the latter option becomes more favorable.

Pipelining is a technique for configuring CPU hardware elements to boost overall performance. In a pipelined processor, multiple instructions can be executed simultaneously by overlapping their stages of execution.

---

**Real World Analogy: Water Bottle Packaging Plant**

Consider a water bottle packaging plant with three stages:
  - **Stage 1 (I):** Insert the bottle
  - **Stage 2 (F):** Fill water in the bottle
  - **Stage 3 (S):** Seal the bottle

Each stage takes 1 minute to complete.

**Without Pipelining (3 bottles):**
```
Bottle 1:  I  F  S  |  |  |  |  |  |
Bottle 2:  |  |  |  I  F  S  |  |  |
Bottle 3:  |  |  |  |  |  |  I  F  S
                                        Total = 9 minutes
```
Average time per bottle = 9 / 3 = **3 minutes**

**With Pipelining (3 bottles):**
```
Bottle 1:  I  F  S  |  |
Bottle 2:  |  I  F  S  |
Bottle 3:  |  |  I  F  S
                           Total = 5 minutes
```
Average time per bottle = 5 / 3 ≈ **1.67 minutes**

Thus, pipelined operation increases the efficiency of the system by keeping all stages active simultaneously.

**Design of a Basic Pipeline**
  - In a pipelined processor, a pipeline has two ends: the input end and the output end.
  - Between these ends, there are multiple stages/segments such that the output of one stage is connected to the input of the next stage, and each stage performs a specific operation.
  - Interface registers (also called latches or buffers) are used to hold the intermediate output between two stages.
  - All the stages in the pipeline, along with the interface registers, are controlled by a common clock.

---

**Execution in a Pipelined Processor**

The execution sequence of instructions in a pipelined processor can be visualized using a space time diagram. For a processor with 4 stages executing 2 instructions:

- Non overlapped execution:
  - Total time = 4 + 4 = 8 cycles

- Overlapped (pipelined) execution:
  - Total time = 4 + (2 − 1) = 5 cycles

---

**RISC 5-Stage Instruction Pipeline**

A RISC processor has a 5-stage instruction pipeline:

**Stage 1: Instruction Fetch (IF)**
  - The CPU reads the instruction from the address in memory whose value is present in the program counter.
    
**Stage 2: Instruction Decode (ID)**
  - The instruction is decoded, and the register file is accessed to get the values from the registers used in the instruction.
    
**Stage 3: Execute (EX)**
  - ALU operations are performed.
    
**Stage 4: Memory Access (MEM)**
  - Memory operands are read from or written to the memory as specified in the instruction.
    
**Stage 5: Write Back (WB)**
  - The computed or fetched value is written back to the register specified in the instruction.

---

**Floating Point Addition Pipeline Stages**

The execution of a floating point addition instruction can be divided into the following stages:
  1. **Fetch** the operands from memory.
  2. **Normalize** the operands (align exponents).
  3. **Perform** the addition.
  4. **Round** the result.

In a pipelined processor, these stages can be overlapped so that multiple floating point instructions can be in different stages of execution at the same time.

**Speedup Equation**

The speedup of a pipelined processor over a non-pipelined processor is given by:

`S = (k × n) / (k + n − 1)`

Where:
  - **k** = number of pipeline stages
  - **n** = number of instructions

**Derivation:**
  - Without pipelining: Total time = k × n cycles (each instruction takes k cycles sequentially).
  - With pipelining: Total time = k + (n − 1) cycles (first instruction takes k cycles; each subsequent instruction completes in 1 additional cycle).
  - Therefore: Speedup = (k × n) / (k + n − 1)

**Properties:**
- As **n → ∞**, the speedup approaches **k** (the theoretical maximum).
- The speedup is always less than or equal to **k**.

**Example 1:** k = 5 stages, n = 20 instructions
- S = (5 × 20) / (5 + 20 − 1) = 100 / 24 ≈ **4.17×**

**Example 2:** k = 4 stages, n = 100 instructions
- S = (4 × 100) / (4 + 100 − 1) = 400 / 103 ≈ **3.88×** (approaching the maximum of 4)

**Discussion**

Pipelining increases the throughput of the processor by utilizing temporal parallelism. That is, all stages of the pipeline execute a different instruction. The time taken for the execution of one instruction is still the same, i.e., it still has to go through all k stages. However, the throughput is higher since a new instruction is fetched into the pipeline every clock cycle once the pipeline is filled.

**Limitations and Hazards**
  - Though in this lab, pipelining is assumed to be ideal, in real-life pipelining, there are three types of hazards:
    - **Data Hazards**:
        - A data hazard occurs when one instruction depends on the output of another instruction, which has not yet completed its Write Back phase. For example, in the following two instructions, the instruction "ADD R2, R1, R3" depends on the output of the instruction "LOAD R1, 0(R5)".
        - This problem can be resolved through data forwarding or by inserting NOPs.

    - **Control Hazards**:
        - These hazards occur when a branch instruction is encountered. The branch instruction does not know what its next instruction is until the branch is resolved. This leads to incorrect fetching of the instruction. This problem is resolved through branch prediction, delayed branching, and speculative execution.

    - **Structural Hazards**:
        - These hazards occur when two or more instructions need the same resource in the same clock cycle. For example, suppose two instructions need to access memory in the same clock cycle. This is resolved by duplicating resources, i.e., having separate instruction and data caches.


**Conclusions**

This lab experiment proved the ideas of pipelining and how it affects processor performance.

In a 4-stage processor with Fetch, Decode, Execute, and Write Back stages, floating point calculations showed how pipelining speeds up execution by doing stages at the same time.

The formula for speedup, `S = (k × n) / (k + n − 1)` was correct. It showed that speedup increases with the number of instructions and gets closer to the number of pipeline stages.

For example, with 5 pipeline stages and 20 instructions, we got a speedup of around 4.17 times.

The space time diagram showed that pipelining can cut execution time from 20 cycles to 8 cycles for 4 instructions in a 5-stage processor.

Pipelining has problems in real processors because of data, control and structural hazards.

These problems are solved using methods, like forwarding, branch prediction and having resources.

Pipelining is still a way to improve processor performance.
